# Partial Code Analysis (코드 부분 분석) 명세

## 1. 개요 (Objective)
사용자가 전체 프로젝트가 아닌 특정 코드 일부(함수, 클래스, 블록 등)를 입력했을 때, **데이터베이스에 저장하지 않고** 즉시 구조(AST)와 품질 메트릭을 분석하여 결과만 반환하는 기능을 구현합니다.
영구적인 저장 로직(DB 등)이 필요 없는 상태 비저장(Stateless) 형태의 분석 프로세스로 동작합니다. 지원하는 언어는 **TypeScript, JavaScript, Python, C, Java** 총 5가지입니다.

## 2. 기술 스택 (Tech Stack)
- **언어:** Node.js, TypeScript (기존 백엔드 프레임워크 활용)
- **파서:** Tree-sitter (`tree-sitter-typescript`, `tree-sitter-javascript`, `tree-sitter-python`, `tree-sitter-c`, `tree-sitter-java`)
- **품질 분석:** 자체 구현된 메트릭 추출 로직 (Cyclomatic Complexity, 응집도/결합도 등)
- **저장소:** **사용 안 함** (No DB, 완전한 일회성 메모리 처리)

## 3. 제약 조건 및 예외 처리 (Constraints & Validation)
단순한 한 줄 입력이나, 구조적으로 무의미한 텍스트 분석을 방지하기 위해 다음의 제약 조건을 적용합니다.
1. **최소 길이 제한:** 코드의 줄 수(Line Count)가 최소 3줄 이상이어야 하며, 문자열 길이가 최소 50자 이상이어야 합니다.
2. **단순 선언문 거부:** Tree-sitter 파싱 결과, 제어문이나 블록(함수, 클래스 등) 구조가 없고 단순 변수 할당문만 1~2개 있는 경우 예외 처리(400 Bad Request)합니다.
3. **최대 길이 제한:** 부분 분석의 목적에 맞게 지나치게 거대한 코드(예: 1000줄 이상)는 파일/프로젝트 단위 분석으로 유도하고 거부합니다.
4. **구문 오류(Syntax Error) 한계:** Tree-sitter가 `ERROR` 노드를 일정 비율 이상 반환하거나 루트 레벨의 심각한 파싱 실패가 일어난 경우, 유효하지 않은 코드 조각으로 간주하여 에러를 반환합니다.

## 4. 구현 단계 (Phases)

### Phase 1: 상태 비저장(Stateless) 분석 인터페이스 및 입력 검증 설계
- **인터페이스:** DB 저장(Create) 행위 없이, 입력값을 받아 즉시 결과를 응답하는 일회성 API 또는 컨트롤러 레이어.
- **요청 데이터:** `{ "code": "string", "language": "typescript | javascript | python | c | java" }`
- **구현 내용:** 
  - DB 모델이나 레포지토리 연동 없이 메모리 상에서 즉시 처리하도록 로직 설계.
  - 위에서 정의한 3항의 제약 조건(길이, 줄 수 등)에 따른 입력값 검증 로직 구현.
  - 지원하는 5개 언어 외의 값이 `language` 필드로 들어오면 적절한 에러(400) 처리.

### Phase 2: Tree-sitter AST 파싱 및 구조적 검증
- **구현 내용:**
  - 요청된 언어(`language`)에 맞는 Tree-sitter 언어 모듈을 동적으로 매핑하여 코드를 AST로 파싱.
  - 파싱된 AST 내에 유효한 코드 블록(함수, 클래스, 메서드 등)이 존재하는지 확인 (단순 할당문 거부).
  - 구문 오류(ERROR 노드) 비율 계산 및 한계치 초과 시 에러 반환 로직 구현.
  - 프론트엔드가 즉시 시각화할 수 있도록 AST를 기존 노드/엣지 포맷으로 변환.

### Phase 3: 품질 메트릭 분석 및 즉각 응답
- **구현 내용:**
  - 파싱된 AST를 순회하며 코드 품질(예: 순환 복잡도, 매개변수 개수, 함수 길이 등) 메트릭 계산.
  - 계산 시, 각 언어별로 다를 수 있는 AST 노드 구조(예: 파이썬의 들여쓰기 기반 블록, C/Java의 중괄호 블록 등)를 고려하여 메트릭 수집.
  - AST 구조 데이터와 계산된 품질 메트릭을 통합하여 즉시 JSON 응답으로 반환 (요청 처리 직후 메모리에서 해제).

## 5. 검증 기준 (Acceptance Criteria)
- [ ] 입력된 코드가 어떤 DB 구조에도 저장되지 않고, 오직 요청에 대한 응답으로만 데이터가 반환되어야 한다.
- [ ] 3줄 미만의 짧은 코드나 의미 없는 텍스트 입력 시 적절한 에러 메시지(400 상태 코드)가 반환되어야 한다.
- [ ] 5개 언어(TypeScript, JavaScript, Python, C, Java) 중 어느 것을 입력하더라도 성공적으로 AST 구조와 품질 분석 결과가 JSON 형태로 반환되어야 한다.
- [ ] 응답된 JSON 포맷이 프론트엔드의 화면 렌더링 요구사항과 정확히 일치해야 한다.
- [ ] `npm run build` 및 린트(Lint) 검증을 에러 없이 통과해야 한다.

## 6. 의존성 (Dependencies)
- **Tree-sitter 파서:** `tree-sitter` 모듈 외에, 각 언어 처리를 위한 `tree-sitter-typescript`, `tree-sitter-javascript`, `tree-sitter-python`, `tree-sitter-c`, `tree-sitter-java` 의존성이 설치되어 있어야 함.
- **데이터베이스 의존성:** 없음 (해당 기능은 DB 스키마나 엔티티 변경을 동반하지 않음).
